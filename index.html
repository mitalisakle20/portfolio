Salesforce Claims & eWarranty Automation Platform

A governed claims warehouse with ERP-readiness controls and human-controlled release gates.

48,026 claims · 0 duplicate IDs
  • SQL Server
  • Salesforce
  • SSIS
  • Idempotency
  • ERP Readiness
Business problem
The Salesforce claims source held ~200 fields with sparse, overlapping, and sometimes contradictory values—no reliable, decision-ready view of a claim existed.
Scale
48,026 claims ingested · 48,026 distinct IDs · 23,707 warranty-repair claims · 10,499 technically ERP-ready · 1,164 ERP review · 3,872 manual review.
Hardest decision
Where to draw the automation line. I kept the pipeline reliable and set every ERP-release and money-moving decision behind a human gate rather than auto-approving claims on incomplete rules.
Architecture
Raw → Snapshot → Resolved → Fact, one decision-ready row per claim, with explicit resolution precedence for dealer, asset, serial, dates, statuses, and amounts. Source-conflict flags preserved, not hidden.
Validation & safeguards
Idempotent raw upsert, unique DB index for permanent duplicate protection, source hashes, current-row indicators, and readiness / manual-review / ERP-review / data-quality / timeliness queues.
Result
A reliable data-and-control foundation for future ERP integration and warranty-service automation—without prematurely automating financial approvals.

Power Automate Integration Suite

Cross-platform SharePoint and SQL synchronization with duplicate-safe, source-ownership-aware workflows.

4 workflows · 643 dealers · ~60m → ~2m
  • Power Automate
  • SharePoint
  • SQL Server
  • OPENJSON
  • REST
Business problem
Dealer, territory, and prospect data lived in separate systems and drifted out of sync; a row-by-row sync took close to an hour.
Scale
4 production-oriented workflows; 643 dealer records synchronized; ~89 prospect records; runtime cut from ~60 minutes to ~2 minutes.
Hardest decision
Moving from row-by-row calls to a single JSON batch processed set-based with SQL OPENJSON, while preserving the rule that one dealer may hold multiple geographies.
Architecture
SharePoint → Power Automate → JSON payload → SQL, plus a SQL resolved view → SharePoint REST partial updates enriched with territory / FSM / TSM / RSM.
Validation & safeguards
Row-count and required-value validation, exact-pair deduplication, insert/update/remove-stale logic, and protection so unrelated SharePoint-managed fields are never erased.
Result
Duplicate-safe cross-platform synchronization with run-level metrics and a ~30× faster dealer sync.
Completed

AEM Enterprise Market Data Pipeline

Fragmented market-data ingestion consolidated into one canonical source and a governed recent/history warehouse.

19M+ raw · 17.2M resolved facts · 0 dup keys
  • SQL Server
  • SSIS
  • Partitioning
  • MERGE
  • Reconciliation
Business problem
Market data arrived through fragmented ingestion into competing raw tables, making a single trusted source impossible.
Scale
19,023,845 clean raw records · 5,043,094 recent + 12,146,658 historical resolved · ~17.2M resolved fact records.
Hardest decision
Moving record classification into governed SQL, using reporting date as the business partition and latest source-post date to resolve duplicate business keys.
Architecture
One canonical raw layer → separate recent and historical fact tables with natural-key uniqueness, partition constraints, and targeted indexing.
Validation & safeguards
Reconciled source, partition, and fact counts end-to-end; redesigned SSIS so classification happened in SQL rather than parallel raw tables.
Result
A single trusted source with a governed recent/history model and zero duplicate business keys.
Completed

Multi-Source Shipment Warehouse

US and Canadian shipment history unified without grain-related duplication, preserving full traceability.

4.64M shipment-detail rows · US & Canada
  • SQL Server
  • WMS
  • CAPA
  • SSIS
  • Grain Resolution
Business problem
Shipment truth was split across WMS header/detail/delivery sources and Canadian CAPA history at different grains.
Scale
4,643,154 shipment-detail records across the United States and Canada.
Hardest decision
Resolving grain differences across shipments, invoices, orders, and serialized units without letting joins inflate quantities or financial totals.
Architecture
Snapshot and resolved warehouse structures preserving shipment, invoice, order, serial/lot, country, and source-system traceability.
Validation & safeguards
Row counts, distinct business identifiers, and source-country totals reconciled against sources.
Result
Two countries of shipment history unified with duplication-safe grain and full traceability.
